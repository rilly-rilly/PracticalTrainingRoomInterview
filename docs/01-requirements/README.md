## 可运行的演示前端

当前仓库已提供一套**假数据演示版**，不需要启动 Java 后端即可完整体验主链路：

```bash
cd frontend
npm install
npm run dev
```

访问 `http://127.0.0.1:5173/`。

- 演示数据保存在浏览器 `localStorage`（键 `trainee-selection-demo-v2`），刷新不丢失；登录页「重置演示数据」可恢复初始状态。
- 接口路径、方法、统一响应体 `{code, message, data}` 与真实后端一致；Axios 通过自定义 adapter 转发到 `src/mock/server.js`，接入真实 Spring Boot 后端时替换 baseURL 即可。
- 业务规则（名额控制、状态机、调剂优先级、事务性导入、越权拦截）全部在 mock 的 Service 等价层实现，前端不做业务判断、不写死数据。

## 5 分钟演示顺序

1. 管理员 `admin` 登录 → 导入账号 → 学生 tab 填入示例 → 解析预览 → 导入，展示成功条数、失败原因与初始密码。
2. 管理员 → 日程与通知，调整意向填报时间窗口（可现场演示窗口关闭后提交返回 410）。
3. 学生 `S2026008` 登录 → 意向填报：3 个平行意向 + 个人简介 + 调剂勾选；再尝试 4 个意向被 422 拒绝。
4. 导师 `T1003` 登录 → 报考学生 → 给陈子豪录入面试评分 → 拟录取（唯一拟录取自动确认，名额 1/3）。
5. 学生 `S2026001` 登录 → 录取状态 → 2 个拟录取中自主选择唯一去向 → 确认后其余变为已放弃。
6. 管理员 → 录取统筹：调整名额上限、执行逾期未确认处理并展示递补补位；补录与调剂页依次执行内部调剂、全院调剂、第三优先级约谈。
7. 管理员 → 结果公示：发布公示（1 天倒计时）→ 提前结束公示 → 学生状态置为已录取。
8. 学生 → 最终结果页查看「已录取」。
9. 学生 → 录取状态页点击「越权访问演示」，展示导师后台接口返回 403。
10. 任一页面展示加载中、空数据、失败重试、无权限（`/403`）四种反馈。

## 当前边界

- 演示版未包含真实 Java 后端、MySQL 与定时任务；逾期未确认由管理员手动触发（可勾选强制演示）。
- 不做短信/邮件、OAuth2/SSO、AI 自动匹配、简历附件、聊天/视频面试、Redis、消息队列、微服务、Docker。
- 密码在 mock 中使用可复现哈希，真实后端按文档 02/03 使用 BCrypt。
